 第一部分：教案生成（核心重点功能，优先级最高）
================================================================================

一、用户设想的完整流程

  老师操作步骤：
  1. 点击侧边栏"教案生成"按钮 --> 弹出教案生成面板
  2. 填写表单：教学目标、学科、年级/难度、课时(分钟)、学生水平
  3. 点击"生成大纲" --> 大模型生成结构化教案提纲(JSON)
  4. 前端渲染提纲预览（可编辑），老师确认/修改后点击"确认并生成"
  5. 系统并发调用：文生图 API + PPT 生成引擎
  6. 完成后展示最终结果，提供下载入口

二、后端改造方案（已有基础，需要增量开发）

  2.1 现有能力（teaching_api/routes/lesson.py 已实现）
  - POST /api/lesson/generate：两阶段生成（提纲 + 并发插图）
  - 提纲结构包含：标题、章节列表（每章含时长、内容、need_image、image_prompt）
  - 图文生成使用百炼 wanx-v1，支持 asyncio.gather 并发

  2.2 需要新增：教案从"确认提纲"到"完稿"的完整链路

  修改 lesson.py 增加以下端点：

  (1) POST /api/lesson/generate_outline
      功能：仅生成提纲，不产生插图
      入参：
        {
          "objective": "教学目标",
          "subject": "学科",
          "level": "初中/高中/大学",
          "duration": 45,
          "student_level": "基础/中等/优秀",
          "style": "严谨/活泼/互动式"
        }
      返回：
        {
          "lesson_id": "uuid",
          "title": "教案标题",
          "sections": [
            {
              "id": "sec_1",
              "title": "导入环节",
              "duration": 5,
              "content": "通过...引入新课",
              "need_image": false,
              "image_prompt": null
            },
            ...
          ],
          "total_duration": 45,
          "status": "outline"
        }

  (2) POST /api/lesson/confirm_outline
      功能：老师确认/修改提纲后，触发并发生成插图和 PPT
      入参：修改后的 sections 数组 + lesson_id
      流程：
        a. 接收前端回传的 sections（可能被老师修改过）
        b. 提取 need_image=true 的 sections
        c. 并发调用 wanx-v1 生成插图（每张约 8-12 秒，4 张并发生成可压缩到约 15 秒）
        d. 将图片 URL 关联到对应 section
        e. 调用 PPT 生成引擎（详见下一节）
        f. 保存生成结果到 data/lessons/{lesson_id}.json
      返回：
        {
          "lesson_id": "uuid",
          "sections": [...],     // 已关联 image_url 的完整数据
          "ppt_url": "/api/lesson/{lesson_id}/ppt",
          "status": "completed"
        }

  (3) GET /api/lesson/{lesson_id}/ppt
      功能：下载生成的 PPT 文件
      返回：Content-Type: application/vnd.openxmlformats-officedocument.presentationml.presentation

  (4) GET /api/lesson/{lesson_id}/image/{section_id}
      功能：代理下载文生图生成的插图（如果百炼返回的是临时 URL）
      避免 CORS 问题，也在服务端做本地缓存

三、PPT 生成方案（重点回答用户疑问）

  问题：制作 PPT 这一步怎么完成？需要加入开源生成 PPT 项目吗？

  答案：不需要引入复杂的开源 PPT 项目。推荐使用 python-pptx 库自建生成引擎。

  方案对比分析：

  ┌──────────────┬────────────────────┬──────────┬──────────┐
  │   方案        │ 方式                │ 复杂度   │ 推荐度    │
  ├──────────────┼────────────────────┼──────────┼──────────┤
  │ python-pptx   │ Python 纯代码生成   │ 中       │ ★★★★★    │
  │               │ .pptx 文件          │          │ (首选)    │
  ├──────────────┼────────────────────┼──────────┼──────────┤
  │ Marp          │ Markdown 转 PPT     │ 低       │ ★★★      │
  │               │ (需 Node.js)        │          │           │
  ├──────────────┼────────────────────┼──────────┼──────────┤
  │ Slidev        │ Vue + Markdown 转   │ 高       │ ★★       │
  │               │ 演示 (需 Node.js)   │          │           │
  ├──────────────┼────────────────────┼──────────┼──────────┤
  │ PptxGenJS     │ 前端 JS 生成        │ 中       │ ★★★      │
  │               │ (浏览器端)          │          │           │
  ├──────────────┼────────────────────┼──────────┼──────────┤
  │ reveal.js     │ HTML 在线演示       │ 低       │ ★        │
  │               │ (非 .pptx)          │          │           │
  └──────────────┴────────────────────┴──────────┴──────────┘

  推荐方案：python-pptx（纯 Python，无外部依赖服务，与现有 FastAPI 后端天然契合）

  3.1 python-pptx 实现方案
      新增文件：teaching_api/services/ppt_service.py

      核心能力：
      - 模板系统：预置 3 套 PPT 模板（教学演示/学术报告/简约白板）
        每套模板定义了：
        * 封面页布局（标题、副标题、日期、作者）
        * 目录页布局
        * 内容页布局（标题 + 正文 + 可选的占位图位置）
        * 总结页布局
      - 智能排版：
        * 根据每段文字的多少自动调整字号
        * 插图自动缩放适配到占位图区域
        * 支持中文标点、数学符号
      - 样式方案：
        * 颜色主题：蓝色学术/绿色清新/紫色科技
        * 字体：黑体(标题) + 宋体(正文)

      生成流程（核心代码逻辑）：
      ```
      1. from pptx import Presentation
      2. prs = Presentation(template_path)  或从零创建
      3. 封面页：slide = prs.slides.add_slide(prs.slide_layouts[0])
                 slide.shapes.title.text = lesson_title
                 slide.shapes.placeholders[1].text = "AI教学助手自动生成"
      4. 目录页：遍历 sections，生成编号列表
      5. 内容页（每个 section 一页）：
                添加标题 shape
                添加正文 text_frame（自动换行/分栏）
                如有 image_url：下载图片并插入到图片占位区域
      6. 总结页
      7. prs.save(f"data/lessons/{lesson_id}.pptx")
      ```

      性能预估：
      - 10 页 PPT 生成 < 5 秒（不含图片下载）
      - 图片下载+嵌入额外 2-3 秒/张

  3.2 兜底方案：如果 python-pptx 样式不够美观
      可以在前端再做一个"美化导出"选项：
      - 前端拿到 sections 数据后，用 PptxGenJS 在浏览器端生成
      - 优势：前端有更多 CSS 经验，可以做更丰富的排版
      - 劣势：图片跨域问题需要后端代理解决

  4.2 技术实现要点（JS 侧）

  使用 SSE（Server-Sent Events）或轮询实现进度状态：
  - confirm_outline 返回后，前端每秒轮询 GET /api/lesson/{lesson_id}/status
  - 或者后端用 SSE streaming 推送进度事件

  ```javascript
  async generateOutline(formData) {
    // 步骤1: 生成大纲
    const res = await fetch('/api/lesson/generate_outline', {
      method: 'POST', headers: {'Content-Type': 'application/json'},
      body: JSON.stringify(formData)
    });
    const data = await res.json();
    this.currentLessonId = data.lesson_id;
    this.renderOutline(data.sections);
  }

  async confirmAndGenerate(modifiedSections) {
    // 步骤2: 确认并触发生成
    const res = await fetch('/api/lesson/confirm_outline', {
      method: 'POST', headers: {'Content-Type': 'application/json'},
      body: JSON.stringify({
        lesson_id: this.currentLessonId,
        sections: modifiedSections
      })
    });
    // 步骤3: SSE 或轮询进度
    this.pollProgress(this.currentLessonId);
  }
  ```

 第二部分：知识图谱（需要看起来真实，但无需真正用于实际）
================================================================================

一、设计定位

  根据用户要求：知识图谱需要"看着真实一点但是无需真正用于实际"，即
  前端展示效果要够专业，但后端可以走模拟数据或简化的 LLM 生成路线。

  理解：这里不是要做一个百万节点的 Neo4j 生产集群，而是做一个"演示级
  但视觉效果好"的知识图谱功能，用于项目答辩和论文展示。

二、后端方案

  2.1 现有能力（teaching_api/routes/knowledge.py）
  - POST /api/knowledge/generate：传入学科+主题，LLM 生成 8-12 个节点
    和关系边
  - GET /api/knowledge/graph/{subject}/{topic}：读取已缓存的知识图谱
  - GET /api/knowledge/subjects：返回预设的 6 个学科列表

  2.2 增强方案

  针对"看起来真实"的需求，做以下增强：

  (1) 预置知识图谱缓存
  - 预先用 LLM 生成 6 个学科、每个学科 3-5 个主题的完整知识图谱，
    存为 JSON 文件在 data/knowledge_graphs/{subject}/{topic}.json
  - 前端请求时直接返回缓存，无需每次等 LLM（300ms 内响应）
  - 这样演示体验非常流畅，不会出现"等 10 秒才出图"

  (2) 节点元数据增强
  每个知识节点增加更多字段让前端展示内容更丰富：
  ```json
  {
    "id": "transformer_arch",
    "name": "Transformer 架构",
    "difficulty": "hard",
    "status": "learning",
    "description": "基于自注意力机制的序列到序列模型架构，由 Vaswani 等人在 2017 年提出，彻底改变了自然语言处理领域",
    "examples": ["BERT", "GPT", "T5"],
    "related_courses": ["深度学习", "自然语言处理"],
    "learning_suggestions": "建议先掌握 RNN 和 LSTM 后再学习"
  }
  ```

  (3) 关系类型丰富
  ```json
  {
    "source": "self_attention",
    "target": "transformer_arch",
    "relation": "core_component",
    "label": "核心组件",
    "description": "Self-Attention 是 Transformer 最核心的机制"
  }
  ```

文件：teaching_api/services/ppt_service.py

```python
"""
PPT 生成服务
基于 python-pptx 从教案 JSON 生成 .pptx 文件
"""
import os
import json
from io import BytesIO
from typing import List, Dict, Optional
from pptx import Presentation
from pptx.util import Inches, Pt, Emu
from pptx.dml.color import RGBColor
from pptx.enum.text import PP_ALIGN, MSO_ANCHOR
from PIL import Image
import requests
from loguru import logger


class PPTStyle:
    ACADEMIC = {
        "bg_color": RGBColor(0xFF, 0xFF, 0xFF),
        "title_color": RGBColor(0x1A, 0x3C, 0x6D),
        "text_color": RGBColor(0x33, 0x33, 0x33),
        "accent_color": RGBColor(0x2B, 0x7A, 0xC2),
        "title_font": "Microsoft YaHei",
        "body_font": "Microsoft YaHei",
    }
    FRESH = {
        "bg_color": RGBColor(0xFA, 0xFC, 0xFF),
        "title_color": RGBColor(0x2D, 0x8C, 0x5A),
        "text_color": RGBColor(0x44, 0x44, 0x44),
        "accent_color": RGBColor(0x5B, 0xB3, 0x81),
        "title_font": "Microsoft YaHei",
        "body_font": "Microsoft YaHei",
    }
    TECH = {
        "bg_color": RGBColor(0x0D, 0x11, 0x17),
        "title_color": RGBColor(0x71, 0x70, 0xFF),
        "text_color": RGBColor(0xE0, 0xE0, 0xE0),
        "accent_color": RGBColor(0x9D, 0x71, 0xFF),
        "title_font": "Microsoft YaHei",
        "body_font": "Microsoft YaHei",
    }


class PPTGenerator:
    def __init__(self, style_name: str = "academic"):
        self.styles = {
            "academic": PPTStyle.ACADEMIC,
            "fresh": PPTStyle.FRESH,
            "tech": PPTStyle.TECH,
        }
        self.style = self.styles.get(style_name, PPTStyle.ACADEMIC)
        self.prs = Presentation()
        self.prs.slide_width = Inches(13.333)
        self.prs.slide_height = Inches(7.5)

    def _download_image(self, url: str) -> Optional[BytesIO]:
        try:
            resp = requests.get(url, timeout=30)
            if resp.status_code == 200:
                return BytesIO(resp.content)
        except Exception as e:
            logger.warning(f"下载图片失败 {url}: {e}")
        return None

    def _add_background(self, slide):
        background = slide.background
        fill = background.fill
        fill.solid()
        fill.fore_color.rgb = self.style["bg_color"]

    def add_cover_slide(self, title: str, subtitle: str = ""):
        slide = self.prs.slides.add_slide(self.prs.slide_layouts[6])
        self._add_background(slide)
        left = Inches(1.5)
        top = Inches(2.5)
        width = Inches(10)
        height = Inches(1.2)
        txBox = slide.shapes.add_textbox(left, top, width, height)
        tf = txBox.text_frame
        p = tf.paragraphs[0]
        p.text = title
        p.font.size = Pt(40)
        p.font.bold = True
        p.font.color.rgb = self.style["title_color"]
        p.font.name = self.style["title_font"]
        p.alignment = PP_ALIGN.CENTER

        if subtitle:
            top2 = Inches(3.8)
            txBox2 = slide.shapes.add_textbox(left, top2, width, Inches(0.8))
            tf2 = txBox2.text_frame
            p2 = tf2.paragraphs[0]
            p2.text = subtitle
            p2.font.size = Pt(18)
            p2.font.color.rgb = self.style["accent_color"]
            p2.alignment = PP_ALIGN.CENTER

    def add_content_slide(self, section_title: str, content: str,
                          image_url: Optional[str] = None):
        slide = self.prs.slides.add_slide(self.prs.slide_layouts[6])
        self._add_background(slide)

        left = Inches(0.8)
        top = Inches(0.5)
        width = Inches(11.5)
        txBox = slide.shapes.add_textbox(left, top, width, Inches(0.7))
        tf = txBox.text_frame
        p = tf.paragraphs[0]
        p.text = section_title
        p.font.size = Pt(28)
        p.font.bold = True
        p.font.color.rgb = self.style["title_color"]

        content_left = Inches(0.8)
        content_top = Inches(1.5)
        if image_url:
            content_width = Inches(6.5)
            img_left = Inches(7.8)
            img_top = Inches(1.5)
            img_data = self._download_image(image_url)
            if img_data:
                slide.shapes.add_picture(img_data, img_left, img_top,
                                         width=Inches(4.8))
        else:
            content_width = Inches(11.5)

        content_height = Inches(5.0)
        txBox2 = slide.shapes.add_textbox(content_left, content_top,
                                          content_width, content_height)
        tf2 = txBox2.text_frame
        tf2.word_wrap = True
        paragraphs = content.split('\n')
        for i, para_text in enumerate(paragraphs):
            if i == 0:
                p = tf2.paragraphs[0]
            else:
                p = tf2.add_paragraph()
            p.text = para_text.strip()
            p.font.size = Pt(16)
            p.font.color.rgb = self.style["text_color"]
            p.space_after = Pt(8)

    def add_toc_slide(self, sections: List[Dict]):
        slide = self.prs.slides.add_slide(self.prs.slide_layouts[6])
        self._add_background(slide)

        txBox = slide.shapes.add_textbox(Inches(1.5), Inches(0.8),
                                         Inches(10), Inches(0.7))
        tf = txBox.text_frame
        p = tf.paragraphs[0]
        p.text = "课程大纲"
        p.font.size = Pt(32)
        p.font.bold = True
        p.font.color.rgb = self.style["title_color"]

        content_tf = slide.shapes.add_textbox(Inches(1.5), Inches(2.0),
                                              Inches(10), Inches(4.5))
        tf2 = content_tf.text_frame
        for i, section in enumerate(sections):
            if i == 0:
                p = tf2.paragraphs[0]
            else:
                p = tf2.add_paragraph()
            p.text = f"{i+1}. {section.get('title', '')} ({section.get('duration', 0)}分钟)"
            p.font.size = Pt(18)
            p.font.color.rgb = self.style["text_color"]
            p.space_after = Pt(12)

    def generate(self, lesson_data: Dict) -> str:
        title = lesson_data.get("title", "AI 生成教案")
        sections = lesson_data.get("sections", [])

        self.add_cover_slide(title, "AI 教学助手自动生成")
        self.add_toc_slide(sections)

        for section in sections:
            self.add_content_slide(
                section_title=section.get("title", ""),
                content=section.get("content", ""),
                image_url=section.get("image_url"),
            )

        output_dir = lesson_data.get("output_dir", "data/lessons")
        os.makedirs(output_dir, exist_ok=True)
        output_path = os.path.join(output_dir, f"{lesson_data.get('lesson_id')}.pptx")
        self.prs.save(output_path)
        return output_path
```

 附录B：关键决策记录

  1. PPT 生成：选用 python-pptx（不引入开源PPT项目）
     理由：纯 Python 零额外服务依赖，与 FastAPI 天然契合，
     安装包仅 200KB，10页PPT生成 < 5秒。

  2. 知识图谱：选用 vis.js Network（不引入 Neo4j 图数据库）
     理由：演示级需求不需要真实图数据库，vis.js CDN引入即可，
     力导向布局效果专业，适合答辩/论文展示。

  3. 图片下载代理：后端统一代理下载文生图URL
     理由：百炼返的是临时URL（可能带CORS限制），后端下载后
     本地托管可避免前端跨域问题，同时做图片本地缓存。

  4. 教案生成前端：三步向导而非单页大表单
     理由：分步引导降低老师操作门槛，提纲确认环节支持人工审核
     再进入耗时生成阶段，避免一步生成后发现提纲不满意而重来。

  5. 前端架构：保持原生 HTML/JS（不引入 Vue/React）
     理由：项目已有完整的原生前端体系，引入框架会增加构建系统
     复杂度。新增 JS 文件采用模块化 class 风格，与现有 videochat.js
     的 VideoChatApp class 保持一致。


 附录C：OpenAvatarChat 与 Teaching API 的关系说明

  当前架构中，app.py（主服务 8282 端口）在 run() 方法中通过 FastAPI
  的 include_router 机制将 teaching_api 的 5 个路由模块注册到主应用：

  app.py:L1096-L1104
  ```
  self.app.include_router(students.router, prefix="/api/students")
  self.app.include_router(memory.router, prefix="/api/memory")
  self.app.include_router(knowledge.router, prefix="/api/knowledge")
  self.app.include_router(lesson.router, prefix="/api/lesson")
  self.app.include_router(evaluation.router, prefix="/api/evaluation")
  ```

  这意味着：
  - 不需要单独启动 teaching_api（它是作为插件集成到主服务的）
  - 所有 API 都在同一个 8282 端口下可用
  - teaching_api 从 app.py 的 glut2.yaml 配置加载时获取 API Key
    （虽然 teaching_api/config.py 有独立的 API Key 配置，但实际
    运行时优先读取环境变量 DASHSCOPE_API_KEY）
